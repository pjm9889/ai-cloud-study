A0. 프로젝트 베이스
설계 원칙 · 규칙 기반 탐지 · 키워드 검색

과정 전체의 베이스를 다진다. 요구사항·가이드 규칙·정답셋을 정하고, 첫 검사기(규칙 기반)와 첫 검색기(TF-IDF·BM25)를 만들어 이후 모든 단계의 기준선을 잡는다.

Part 1 · 프로젝트 소개와 설계 원칙

1.1 어떤 프로젝트인가

웹 설계 정합성 판정 에이전트: 웹페이지가 표준·가이드를 지키는지 근거와 함께 판정한다.

이름과 판정 용어

항목내용
프로젝트 이름웹 설계 정합성 판정 에이전트 (Conformance Checking Agent)
판정하는 정합성① 가이드 ↔ 표준: 사내 가이드가 WCAG·KWCAG와 어긋나지 않는가
② 페이지 ↔ 가이드·표준: 실제 페이지가 규칙을 지키는가
판정 결과적합 / 부적합: 표준·가이드 규칙 기준의 판정
권고: 정답이 없는 UX 휴리스틱 의견 (B6)
용어 구분정합성: 두 대상이 어긋나지 않음 (프로젝트 이름) · 적합성: WCAG 공식 용어 Conformance · 준수: KWCAG·법령 용어

웹페이지 작업의 두 가지 기준

프론트엔드 작업물은 두 종류의 기준을 동시에 지켜야 한다. 이 프로젝트는 둘 다를 판정 규칙으로 바꾼다.

구분국제·국가 표준사내 디자인 가이드
만드는 곳W3C, 국가 기관, 표준화 기구회사의 디자인·프론트엔드 팀
목적누구나 쓸 수 있는 웹 (접근성, 호환성)제품 전체의 일관된 화면과 경험
효력법·인증·조달 요건과 연결팀 내부 약속, 리뷰 기준
표현 방식"텍스트 대비 4.5:1 이상"처럼 결과 기준"본문 #333, 버튼 높이 44px"처럼 구체적 값
관계최소 기준표준과 같거나 더 엄격해야 한다

표준 문서와 담긴 내용

문서 이름을 누르면 원문이 열린다.

문서만든 곳담긴 내용이 프로젝트에서
WCAG 2.2
Web Content Accessibility Guidelines
W3C웹 접근성 국제 표준. 4원칙(인식·운용·이해·견고) 아래 성공 기준 80여 개를 A·AA·AAA 등급으로 정의. 예: 대체 텍스트(1.1.1), 명도 대비(1.4.3), 키보드 조작(2.1.1), 링크 목적(2.4.4), 입력 레이블(3.3.2)모든 규칙의 근거 조항. 목표 등급은 AA
KWCAG 2.2
Korean Web Content Accessibility Guidelines · 국가표준 KS X OT0003:2022
국내 (과학기술정보통신부 소관)WCAG를 국내 실정에 맞게 반영한 한국형 지침. 4원칙·14지침·33검사항목. 웹 접근성 품질인증 심사 기준국내 서비스 기준선, 공공·인증 대상일 때 필수
WAI-ARIA 1.2
Web Accessibility Initiative – Accessible Rich Internet Applications
W3C모달·탭·토스트 같은 커스텀 컴포넌트의 역할(role), 상태(aria-expanded 등), 이름(aria-label)을 보조기술에 알리는 방법링크·버튼의 aria-label 판정, 이후 모달·토스트 규칙
HTML 표준
HTML Living Standard
WHATWG요소의 의미와 올바른 사용. <button>, <label>, <nav>, <main> 같은 시맨틱 요소DOM 추출과 component 분류의 기준
EN 301 549
European Norm 301 549
유럽 표준화 기구유럽 접근성법(EAA)의 기준 표준. 웹 부분은 WCAG 2.1 AA를 그대로 참조해외 서비스로 확장할 때의 기준

사내 디자인 가이드에 담기는 내용

표준이 "무엇을 만족해야 하는가"라면, 가이드는 "우리 제품에서는 이렇게 한다"를 정한다.

영역가이드 내용 예연결된 표준
색상 · 대비텍스트·배경 색 조합 목록, 보조 텍스트 최소 색상WCAG 1.4.3, 1.4.11
타이포그래피글자 크기 단계, 줄 간격, 200% 확대 시 레이아웃 유지WCAG 1.4.4, 1.4.12
버튼 · 링크최소 터치 크기 44px, 포커스 표시 스타일, 링크 문구 작성법WCAG 2.5.8, 2.4.7, 2.4.4
폼레이블 위치, placeholder 사용 금지 범위, 에러 문구 형식WCAG 3.3.1, 3.3.2, 3.3.3
이미지 · 아이콘alt 작성 원칙, 장식 이미지 처리, 아이콘 버튼 이름WCAG 1.1.1
컴포넌트모달·토스트·탭의 동작, 포커스 이동, 사용할 공통 컴포넌트WCAG 2.1.2, 4.1.2, WAI-ARIA
문구 (UX 라이팅)버튼·에러·안내 문구의 어조와 형식WCAG 3.3.3, UX 휴리스틱

가이드는 표준을 대신하지 않는다. 가이드에 "보조 텍스트 #AAA"라고 적으면 흰 배경에서 대비 기준(4.5:1)을 넘지 못해, 가이드를 지켰는데 표준은 어기는 일이 생긴다. 그래서 A0의 모든 가이드 규칙에는 WCAG 조항이 붙는다.

지키지 않으면 생기는 문제

영역문제예
사용자장애인·고령자가 서비스를 쓰지 못한다스크린리더가 alt="이미지"만 읽어 배너 내용을 알 수 없음. 키보드 사용자가 모달 안에 갇힘. 저시력 사용자가 연회색 글자를 못 읽음
법 (국내)장애인차별금지법상 웹 접근성 의무 위반국가인권위원회 권고 → 법무부 시정명령, 시정명령 불이행 시 3천만 원 이하 과태료. 악의적 차별은 형사처벌 대상. 지능정보화 기본법도 접근성 준수를 요구
법 (해외)유럽 접근성법(EAA) 위반2025년 6월 28일부터 EU 대상 전자상거래·금융 등 서비스에 적용. 회원국별 벌금, 시장 퇴출 가능
사업매출·기회 손실결제 폼에서 막힌 사용자 이탈, 웹 접근성 인증이 필요한 공공 사업 참여 불가
개발비용 증가화면마다 다른 패턴으로 유지보수 부담, 배포 후 발견된 위반은 수정 범위와 비용이 커짐

그래서 이 프로젝트가 하는 일

표준과 사내 가이드를 판정 규칙으로 바꾸고, 페이지를 자동으로 판정해 부적합마다 근거 규칙을 붙인다. 지금까지 사람이 눈으로 하던 판정을 같은 기준·같은 결과로 반복할 수 있게 만드는 것이 목표다.

설계 결정 기록 (ADR)

결정 하나와 버린 대안, 그 이유를 남긴다. 첫 ADR은 규칙 저장 위치다.

# ADR-001. 가이드 규칙의 원본은 Git의 YAML 파일로 둔다

## 맥락
규칙이 바뀌면 탐지 결과가 바뀐다.
변경 이력과 과거 결과 재현이 필요하다. (문제 ④)

## 결정
원본은 Git의 YAML, PR 리뷰 후 병합.
병합된 규칙은 버전을 붙여 MySQL에 스냅샷 저장.

## 검토한 대안
- MySQL에 직접 저장: 변경 이력·리뷰 절차를 따로 만들어야 함
- MongoDB에 문서로 저장: 규칙은 WCAG·위반·결과와 조인 관계라 맞지 않음

## 결과
- 규칙 변경이 코드 리뷰가 됨
- 결과에 규칙 버전이 남아 재현 가능 (NFR-01, NFR-02)
- A6에서 규칙 변경 PR이 평가 CI를 실행하는 기반
