웹페이지 설계 원칙 검사 에이전트
커리큘럼

공통 소재는 "웹페이지가 설계 원칙(WCAG·디자인 가이드·UI/UX 이론)을 지키는지 검사하는 RAG 에이전트"이고, 같은 소재로 직무마다 다른 역량이 증명되는 포트폴리오가 나오게 설계한 과정이다.

모든 판단은 근거를 가지고, 모든 근거는 추적되고, 모든 결과는 검증된다.

과정 원칙

항목내용
반복 패턴빠르게 만든다 → 측정한다 → 근거를 갖고 재설계한다. 규칙 v1→v2, ChromaDB→OpenSearch, 파이프라인→ReAct→LangGraph, 단일→멀티에이전트
대상 직군시스템 엔지니어, AI 클라우드, 데브옵스, 데이터 분석가
진행 방식코드는 완성본 제공. 강의는 설계 판단과 측정에 집중. 처음 보는 기술(Kiwi, BM25 등)은 자세히, 이미 아는 기술은 역할만
언어전 과정 Python. 화면은 FastAPI + Jinja2
문서 규칙탭마다 약자 첫 등장에 원어 병기, 용어집 제공, 표준 문서는 원문 링크

#핵심 내용통합 실습
A0웹 작업 기준(표준·가이드)과 SRS. 표준·가이드 매핑 후 규칙 YAML과 정답셋. Kiwi 토큰화(품사·사용자 사전). 규칙 v1(함수) → v2(Rules as Code). DOM → component 메타데이터 분류. Kiwi 토큰으로 TF-IDF·BM25 직접 계산해 근거 규칙 검색button 컴포넌트를 매핑 → 규칙 → 테스트 페이지 위반 → 정답셋까지 추가하고 재평가
A1트랜스포머 개념(토큰 → 임베딩 → 어텐션 → 다음 토큰, 인코더 vs 디코더). 토큰화 계층 지도(Kiwi / Nori / HF 토크나이저 / tiktoken). 규칙이 놓친 사례를 LLM이 판단하는 프롬프트, 구조화 출력과 규칙 ID 실존 검증. LLM 응답 캐시와 프롬프트 캐싱규칙 + LLM 판단으로 정답셋 재평가, 재현율 상승분·새 오탐·캐시 절감 정리. 배포 #1
A2코사인 유사도·거리 직접 계산. A0의 TF-IDF 벡터와 임베딩 비교, 어텐션이 내적 기반 유사도라는 연결. 가이드 규칙 임베딩을 component별로 시각화. HF 토크나이저로 BGE-M3 sparse 가중치 해석OpenAI 임베딩 vs BGE-M3 시각화 비교, 한국어 가이드 구분력 판단
A3벡터 저장소 세 유형(임베디드 Chroma / 관리형 Pinecone / 검색엔진형 OpenSearch). MongoDB 기초와 집계. MySQL·MongoDB·벡터DB 역할 분리 ADR. OpenSearch 인덱스 매핑, Nori, 사용자 사전. 임베딩 캐시와 바뀐 청크만 재색인필터 없음 / 하드 필터 / 실패 시 필터 해제 재검색 비교
A4색인·질의 파이프라인. 탐지된 위반에서 질의를 만들어 가이드를 검색하고 근거를 인용한 설명·수정안 생성. 에이전트 v1을 바이브코딩으로 연결하고 불편 메모 작성테스트 사이트 전체로 근거 붙은 리포트 생성, 검증 차단율 기록. 배포 #2
A5청킹 전략(고정, 오버랩, 재귀, 규칙 1개 = 청크 1개), HF 토크나이저 기준 청크 크기. A0의 BM25를 하이브리드에 투입: 애플리케이션 레벨(EnsembleRetriever)과 엔진 레벨(OpenSearch 검색 파이프라인) 비교. Chroma → OpenSearch 이전. 검색 결과 캐시청킹 × 검색 구성 실험표와 최종 구성 ADR, 신뢰구간 분석 리포트
A6정답셋 평가를 배포 관문으로, Argo CD GitOps, 추적성 매트릭스, 오탐 피드백 루프, 관측성 스택 통일, 캐시 적중률·절감 지표품질 하락 변경을 넣어 배포 차단 확인, Grafana로 추적, 추적성 매트릭스로 원인 규칙 찾기. 배포 #3

캐시 키 = 입력 해시 + 버전
입력 해시
텍스트 · 요소 · DOM · 프롬프트 · 청크
버전
규칙 · 도구 · 모델 · 프롬프트 · 인덱스
캐시 키
같은 키면 재사용, 다르면 새로 계산
삭제 로직 없이 무효화된다 · NFR-01 재현성과 같은 원리
