1흐름 설계 이슈RAGLangGraph 필수

왜 설계가 먼저인가

노드가 "무엇을 할지"라면 엣지는 "다음에 누가 실행될지"입니다. 흐름을 잘못 설계하면 처음 보는 입력에서 멈추거나, 두 노드가 함께 실행되거나, 루프가 끝나지 않습니다. 그래서 노드 사이의 연결마다 아래 질문에 답한 뒤 도구를 고릅니다.

연결마다 던질 5가지 질문

Q1. 다음 노드가 항상 같은가?
그렇다면 add_edge. 가장 단순하고 가장 안전합니다.
Q2. 상태를 보고 정해진 후보 중에서 고르나?
add_conditional_edges. 라우터는 고르기만 하고 상태는 바꾸지 못합니다. 후보 목록(라우터가 돌려줄 수 있는 값 전부)을 먼저 적어 둡니다.
Q3. 고르면서 상태도 바꿔야 하나?
판단 결과를 기록하거나(의도, 담당자) 다른 에이전트에게 넘길 때는 Command(goto=..., update=...). 이 노드에서 나가는 고정 엣지는 만들지 않습니다.
Q4. 몇 갈래로 갈지가 실행 중에 정해지나?
문서 수, 하위 질문 수처럼 개수가 바뀌면 Send. 갈래마다 다른 입력을 주고, 결과를 모을 키에는 리듀서가 필요합니다.
Q5. 되돌아가는 길(루프)이 있나?
있다면 종료 조건, 횟수를 세는 상태, recursion_limit 세 가지를 함께 설계합니다.

질문의 답 → 도구

상황도구RAG · 에이전트 예
고정 순서add_edgeretrieve → generate
후보 중 선택add_conditional_edges문서 평가 후 generate / rewrite, ReAct의 tools / END
선택 + 기록Command의도 분류하며 intent 저장, 에이전트 간 핸드오프, HITL 재개
개수가 바뀌는 병렬Send + 리듀서문서 N개 요약, 질문을 쪼개 동시 검색
루프조건부 엣지 + 횟수 상태 + recursion_limit재검색 RAG, ReAct 반복

설계를 안 하면 생기는 5가지 문제

두 노드가 함께 실행Command와 고정 엣지를 같이 씀 (Q3)Command 노드의 고정 엣지 삭제M2

무한 루프 주의 LangGraph 1.2.x의 기본 recursion_limit은 10007입니다. 종료 조건이 틀리면 LLM을 1만 번 가까이 부른 뒤에야 멈출 수 있습니다. 루프가 있는 그래프는 invoke(..., {"recursion_limit": 20})처럼 직접 지정하세요.

2핵심 문법 한 장LangGraph 필수

노드 함수: 받을 수 있는 인자 3가지

from langchain_core.runnables import RunnableConfig
from langgraph.types import StreamWriter

def node_a(state):                                  # 기본: 상태만
    return {"answer": "..."}

def node_b(state, config: RunnableConfig):          # 실행 설정 받기
    model = config["configurable"].get("model", "gpt-4o-mini")
    return {"answer": f"{model}로 답변"}

def node_c(state, *, writer: StreamWriter):         # 진행 상황 스트리밍 (이름은 writer)
    writer({"progress": "검색 중"})
    return {"answer": "..."}

app.invoke({...}, {"configurable": {"model": "gpt-4o"}})   # node_b 에 전달됨

조건부 엣지: 라우터 함수 + 후보

from typing import Literal

def route(state) -> Literal["generate", "rewrite"]:    # 반환 후보를 타입힌트로 명시
    return "generate" if state["score"] >= 0.7 else "rewrite"

g.add_conditional_edges("grade", route)                                    # ① Literal 로 후보 전달
g.add_conditional_edges("grade", route, ["generate", "rewrite"])           # ② 리스트로 후보 전달
g.add_conditional_edges("grade", route, {"generate": "gen", "rewrite": "rw"})  # ③ 반환값 → 노드 이름 맵

③의 맵을 쓰면 라우터가 맵에 없는 값을 돌려줄 때 KeyError가 납니다. 리스트를 반환하면 여러 노드가 동시에 실행됩니다.

Command: 이동 + 상태 업데이트

from langgraph.types import Command

def classify(state) -> Command[Literal["billing", "tech"]]:   # 타입힌트가 있어야 그래프 그림에 엣지가 보임
    if "환불" in state["text"]:
        return Command(goto="billing", update={"intent": "billing"})
    return Command(goto="tech", update={"intent": "tech"})

g.add_edge(START, "classify")      # classify 에서 나가는 add_edge 는 만들지 않는다

Send: 개수가 정해지지 않은 병렬

from langgraph.types import Send

def fan_out(state):                                   # 조건부 엣지 자리에서 Send 리스트 반환
    return [Send("summarize", {"doc": d}) for d in state["docs"]]

g.add_conditional_edges("load", fan_out, ["summarize"])
# summarize 는 {"doc": ...} 만 받고, {"summaries": [...]} 를 돌려준다 → summaries 에는 add 리듀서 필수

실행

app.invoke(입력, {"recursion_limit": 20})                       # 최종 상태
for upd in app.stream(입력, stream_mode="updates"):            # 노드별로 바뀐 부분만
    print(upd)
await app.ainvoke(입력)                                          # 비동기
디버깅 습관 흐름이 이상하면 stream_mode="updates"로 실행해 "어떤 노드가 어떤 순서로 무엇을 바꿨는지"부터 확인합니다. 실제예와 미션 답안도 모두 이 방법으로 출력을 보여 줍니다.

3실제예 ① 사내 규정 재검색 RAGRAGLangGraph 필수

STEP 1 · 상황 읽기

사내 규정 챗봇이 "연차 며칠?" 같은 짧은 질문에서는 관련 문서를 잘 못 찾습니다. 검색 점수가 낮으면 질문을 고쳐 다시 검색하고, 두 번 고쳐도 안 되면 담당자에게 넘기기로 했습니다.

STEP 2 · 흐름 설계 (연결마다 Q1~Q5)
연결판단도구
START → retrieveQ1 항상 같음add_edge
retrieve → ?Q2 점수와 횟수를 보고 generate / rewrite / fallback 중 선택조건부 엣지
rewrite → retrieveQ5 루프 → 종료 조건(점수 ≥ 0.7 또는 재시도 ≥ 2), 횟수 상태 retryadd_edge + 카운터
generate, fallback → ENDQ1add_edge
START→retrieve→route→generate/rewrite ↺/fallback→END
STEP 3 · 상태와 노드
from typing import Annotated, Literal
from typing_extensions import TypedDict
from operator import add
from langgraph.graph import StateGraph, START, END

class RagState(TypedDict):
    query: str
    score: float
    retry: Annotated[int, add]       # 노드는 이번 몫(1)만 돌려준다 (01 리듀서 M3)
    answer: str

def retrieve(s):
    score = 0.85 if "사내" in s["query"] else 0.40      # 가짜 검색 점수
    return {"score": score}

def rewrite(s):
    return {"query": s["query"] + " 사내 규정", "retry": 1}

def generate(s): return {"answer": f"[{s['query']}] 근거로 답변"}
def fallback(s): return {"answer": "관련 규정을 찾지 못했습니다. 담당자에게 연결합니다."}
STEP 4 · 라우터와 연결
def route_after_retrieve(s) -> Literal["generate", "rewrite", "fallback"]:
    if s["score"] >= 0.7:
        return "generate"
    if s["retry"] >= 2:              # 종료 조건 ② : 횟수 초과
        return "fallback"
    return "rewrite"

g = StateGraph(RagState)
for n, f in [("retrieve", retrieve), ("rewrite", rewrite),
             ("generate", generate), ("fallback", fallback)]:
    g.add_node(n, f)
g.add_edge(START, "retrieve")
g.add_conditional_edges("retrieve", route_after_retrieve)   # Literal 이 후보 목록
g.add_edge("rewrite", "retrieve")                            # 루프
g.add_edge("generate", END); g.add_edge("fallback", END)
rag = g.compile()

for upd in rag.stream({"query": "연차 며칠?", "score": 0.0, "retry": 0, "answer": ""},
                      {"recursion_limit": 20}, stream_mode="updates"):
    print(upd)
STEP 5 · 결과 확인
{'retrieve': {'score': 0.4}}
{'rewrite': {'query': '연차 며칠? 사내 규정', 'retry': 1}}
{'retrieve': {'score': 0.85}}
{'generate': {'answer': '[연차 며칠? 사내 규정] 근거로 답변'}}
  1. 라우터는 읽기만. 점수와 횟수를 읽어 이름만 돌려줍니다. 횟수 증가는 rewrite 노드가 합니다.
  2. 루프에는 탈출구 두 개. 성공(점수)과 포기(횟수). 포기 경로가 없으면 점수가 끝내 안 오를 때 무한 루프입니다.
  3. stream으로 확인. 어떤 노드가 몇 번 돌았는지 한눈에 보입니다.

4실제예 ② 고객센터 문의 라우팅LangGraph 필수MCP·에이전트

STEP 1 · 상황 읽기

고객 문의를 결제팀 · 기술지원 · 상담원 중 한 곳으로 보냅니다. 나중에 통계를 내려고 분류 결과(intent)도 상태에 남겨야 합니다.

STEP 2 · 흐름 설계
연결판단도구
classify → ?Q2 후보 중 선택 + Q3 상태(intent)도 기록Command
각 팀 → ENDQ1add_edge

조건부 엣지로도 만들 수 있지만, 그러면 "분류해서 intent 저장하는 노드" + "intent를 읽어 이름을 돌려주는 라우터" 두 개가 필요합니다. Command는 판단한 자리에서 이동과 기록을 함께 합니다.

STEP 3 · Command 노드
from langgraph.types import Command

class CsState(TypedDict):
    text: str
    intent: str
    answer: str

def classify(s) -> Command[Literal["billing", "tech", "human"]]:
    t = s["text"]
    if "환불" in t or "결제" in t:
        return Command(goto="billing", update={"intent": "billing"})
    if "오류" in t or "로그인" in t:
        return Command(goto="tech", update={"intent": "tech"})
    return Command(goto="human", update={"intent": "unknown"})      # 기본 경로

def billing(s): return {"answer": "결제팀 안내: 환불은 14일 이내"}
def tech(s):    return {"answer": "기술지원 안내: 캐시 삭제 후 재로그인"}
def human(s):   return {"answer": "상담원에게 연결합니다"}
STEP 4 · 연결 (classify 에서 나가는 add_edge 없음)
g = StateGraph(CsState)
for n, f in [("classify", classify), ("billing", billing), ("tech", tech), ("human", human)]:
    g.add_node(n, f)
g.add_edge(START, "classify")
for n in ["billing", "tech", "human"]:
    g.add_edge(n, END)
cs = g.compile()

for t in ["환불하고 싶어요", "로그인 오류가 나요", "배송지 바꿔주세요"]:
    print(cs.invoke({"text": t, "intent": "", "answer": ""}))
STEP 5 · 결과 확인
{'text': '환불하고 싶어요', 'intent': 'billing', 'answer': '결제팀 안내: 환불은 14일 이내'}
{'text': '로그인 오류가 나요', 'intent': 'tech', 'answer': '기술지원 안내: 캐시 삭제 후 재로그인'}
{'text': '배송지 바꿔주세요', 'intent': 'unknown', 'answer': '상담원에게 연결합니다'}
  1. Command = 이동 + 기록. 멀티 에이전트의 "핸드오프"도 같은 모양입니다(다른 에이전트로 goto + 넘길 정보 update).
  2. 기본 경로를 꼭 둔다. 마지막 return이 처음 보는 문의를 받습니다 → M1
  3. 고정 엣지와 섞지 않는다. classify에 add_edge를 더하면 두 곳이 함께 실행됩니다 → M2
★ 기본LangGraph 필수

M1. 처음 보는 문의에 터지는 사내 헬프봇

STEP 1 · 상황 읽기

비밀번호·연차 문의는 잘 처리하던 헬프봇이 "환불 되나요?"에서 멈췄습니다.

class FaqState(TypedDict):
    text: str
    intent: str
    answer: str

def classify(s):
    t = s["text"]
    if "비밀번호" in t: return {"intent": "password"}
    if "연차" in t:    return {"intent": "leave"}
    if "환불" in t:    return {"intent": "refund"}
    return {"intent": "etc"}

def route(s): return s["intent"]

def password(s): return {"answer": "비밀번호 초기화 링크를 보냈습니다"}
def leave(s):    return {"answer": "연차는 인사시스템에서 확인하세요"}
def human(s):    return {"answer": "담당자에게 연결합니다"}

g = StateGraph(FaqState)
for n, f in [("classify", classify), ("password", password), ("leave", leave), ("human", human)]:
    g.add_node(n, f)
g.add_edge(START, "classify")
g.add_conditional_edges("classify", route, {"password": "password", "leave": "leave"})
for n in ["password", "leave", "human"]:
    g.add_edge(n, END)
app = g.compile()
for t in ["비밀번호를 잊었어요", "연차 며칠 남았죠?", "환불 되나요?"]:
    print(app.invoke({"text": t, "intent": "", "answer": ""})["answer"])
STEP 2 · 설계 점검 (Q2)

라우터 route가 돌려줄 수 있는 값을 전부 적고, 경로 맵의 키와 비교하세요. human 노드는 어디서 들어오나요?

확인

M2. 품절로 취소했는데 결제도 됐다

STEP 1 · 상황 읽기

조건부 엣지로 만든 주문 그래프를 Command 방식으로 바꿨습니다. 그런데 품절 상품을 주문했더니 "주문 취소"와 "결제 완료"가 둘 다 찍혔습니다.

class OrderState(TypedDict):
    item: str
    qty: int
    log: Annotated[list[str], add]

STOCK = {"사과": 10, "오렌지": 0}

def check_stock(s) -> Command[Literal["pay", "cancel"]]:
    if STOCK.get(s["item"], 0) >= s["qty"]:
        return Command(goto="pay", update={"log": ["재고 확인"]})
    return Command(goto="cancel", update={"log": ["재고 부족"]})

def pay(s):    return {"log": ["결제 완료"]}
def cancel(s): return {"log": ["주문 취소"]}

g = StateGraph(OrderState)
for n, f in [("check_stock", check_stock), ("pay", pay), ("cancel", cancel)]:
    g.add_node(n, f)
g.add_edge(START, "check_stock")
g.add_edge("check_stock", "pay")          # 예전 코드에서 남은 줄
g.add_edge("pay", END); g.add_edge("cancel", END)
print(g.compile().invoke({"item": "오렌지", "qty": 2, "log": []}))
STEP 2 · 설계 점검 (Q1 vs Q3)

check_stock에서 나가는 길을 정하는 것이 몇 개인지 세어 보세요. Command의 goto와 add_edge는 서로를 지울까요, 더해질까요?

확인

두 개입니다: Command의 goto("cancel")와 고정 엣지(check_stock → pay). 둘은 더해집니다. 그래서 같은 단계에서 cancel과 pay가 함께 실행됩니다.

M3. 끝나지 않는 재검색

STEP 1 · 상황 읽기

실제예 ①을 본 동료가 "재시도 3번까지"를 라우터 안에서 세도록 만들었습니다. 검색 점수가 계속 낮자 그래프가 멈추지 않습니다.

class LoopState(TypedDict):
    query: str
    score: float
    retry: int

def retrieve(s): return {"score": 0.3}                 # 늘 낮은 점수
def rewrite(s):  return {"query": s["query"] + "+"}
def generate(s): return {}
def fallback(s): return {}

def route(s):
    if s["score"] >= 0.7:
        return "generate"
    s["retry"] += 1                                     # 라우터에서 횟수 증가
    return "rewrite" if s["retry"] < 3 else "fallback"

g = StateGraph(LoopState)
for n, f in [("retrieve", retrieve), ("rewrite", rewrite),
             ("generate", generate), ("fallback", fallback)]:
    g.add_node(n, f)
g.add_edge(START, "retrieve")
g.add_conditional_edges("retrieve", route, ["generate", "rewrite", "fallback"])
g.add_edge("rewrite", "retrieve")
g.add_edge("generate", END); g.add_edge("fallback", END)
g.compile().invoke({"query": "연차", "score": 0.0, "retry": 0}, {"recursion_limit": 20})
STEP 2 · 설계 점검 (Q2, Q5)

종료 조건은 있습니다. 그런데 왜 도달하지 못할까요? "라우터는 무엇을 할 수 있고 무엇을 못 하나"로 설명하세요.

확인

라우터는 다음 노드 이름만 돌려줍니다. 라우터 안에서 s["retry"] += 1을 해도 상태에 저장되지 않아 retry는 매번 0입니다. 상태를 바꾸는 것은 노드의 반환값(또는 Command의 update)뿐입니다.

STEP 3 · 결과 예측
실제 출력
GraphRecursionError: Recursion limit of 20 reached without hitting a stop condition.

recursion_limit을 지정하지 않았다면 기본값 10007까지 돌았을 것입니다. 실제 LLM이었다면 비용이 그대로 청구됩니다.

STEP 4 · 고치기

횟수를 올리는 책임을 노드로 옮기세요. 라우터는 읽기만 합니다.

예시 답안 보기

    return {"query": s["query"] + "+", "retry": s["retry"] + 1}   # 노드가 올린다

def route(s):
    if s["score"] >= 0.7:
        return "generate"
    return "rewrite" if s["retry"] < 3 else "fallback"          # 라우터는 읽기만

{'retrieve': {'score': 0.3}}
{'rewrite': {'query': '연차++', 'retry': 2}}

STEP 5 · 확인
계산 확인

retrieve 4번 + rewrite 3번 + fallback 1번 = 8단계. 실제로 돌려 보면 한도 8에서는 에러, 9부터 통과합니다(실행 단계 수보다 커야 함). 여유를 두고 10~20으로 지정합니다. 한도는 "정상 흐름이 쓰는 단계 수"보다 조금 크게 잡습니다.

M4. 검색된 문서 N개를 동시에 요약하기

STEP 1 · 상황 읽기

검색 결과는 질문마다 1개일 수도, 10개일 수도 있습니다. 문서마다 따로 요약(LLM 호출)을 동시에 돌리고, 끝나면 보고서 노드가 한 번만 실행되게 하려 합니다.

from langgraph.types import Send

class MapState(TypedDict):
    docs: list[str]
    summaries: list[str]
    report: str

def fan_out(s):
    return [Send("summarize", {"doc": d}) for d in s["docs"]]

def summarize(s: dict):                       # Send 로 받은 {"doc": ...} 만 보인다
    return {"summaries": [s["doc"][:6] + "… 요약"]}

def report(s):
    return {"report": f"{len(s['summaries'])}건 요약 완료"}

g = StateGraph(MapState)
g.add_node("summarize", summarize); g.add_node("report", report)
g.add_conditional_edges(START, fan_out, ["summarize"])
g.add_edge("summarize", "report"); g.add_edge("report", END)

DOCS = ["휴가 규정: 연차는 15일", "출장 규정: 일비 5만원", "보안 규정: 비밀번호 90일"]
g.compile().invoke({"docs": DOCS, "summaries": [], "report": ""})

M5. 미니 ReAct 에이전트의 흐름 만들기

STEP 1 · 상황 읽기

IT 헬프데스크 에이전트를 만듭니다. LLM이 도구가 필요하다고 판단하면 도구를 실행하고 그 결과를 다시 LLM에게 보여 주며, 도구가 필요 없으면 답하고 끝냅니다. 이것이 ReAct 루프입니다. LLM은 아래 가짜 함수로 대신합니다.

from typing import Literal
from langgraph.graph import StateGraph, MessagesState, START, END
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage

def fake_llm(messages):                      # 진짜 LLM 대신
    last = messages[-1]
    if isinstance(last, HumanMessage) and "VPN" in last.content:
        return AIMessage(content="", tool_calls=[{"name": "check_vpn", "args": {}, "id": "call_1"}])
    if isinstance(last, ToolMessage):
        return AIMessage(content=f"점검 결과: {last.content}. 재접속해 보세요.")
    return AIMessage(content="무엇을 도와드릴까요?")

TOOLS = {"check_vpn": lambda: "VPN 서버 정상"}
STEP 2 · 흐름 설계

노드는 agent, tools 두 개입니다. 아래 표의 빈칸(도구, 판단 기준)을 채우세요.

# | 연결            | Q1~Q5 판단 | 도구 | 판단 기준 |
# | START → agent   |            |      |           |
# | agent → ?       |            |      |           |
# | tools → ?       |            |      |           |
설계표 확인
연결판단도구판단 기준
START → agentQ1add_edge-
agent → ?Q2 tools / END 중 선택, Q5 루프조건부 엣지마지막 메시지에 tool_calls가 있는가
tools → agentQ1 (루프의 되돌아가는 길)add_edge-

상태는 MessagesState(01 리듀서의 add_messages)를 씁니다. 대화와 도구 결과가 모두 messages에 쌓입니다.

STEP 3 · 노드 두 개와 라우터 작성

① agent: fake_llm을 호출해 AIMessage를 추가 ② tools: 마지막 AIMessage의 tool_calls마다 TOOLS를 실행해 ToolMessage(tool_call_id 일치)를 추가 ③ should_continue: tools 또는 END 반환

힌트 보기

도구 호출 정보는 s["messages"][-1].tool_calls에 [{"name": ..., "args": ..., "id": ...}] 형태로 들어 있습니다. 라우터는 getattr(last, "tool_calls", None)로 확인하면 안전합니다.

예시 답안 보기
def agent(s: MessagesState):
    return {"messages": [fake_llm(s["messages"])]}

def tools(s: MessagesState):
    last = s["messages"][-1]
    return {"messages": [ToolMessage(content=TOOLS[c["name"]](), tool_call_id=c["id"])
                         for c in last.tool_calls]}

def should_continue(s: MessagesState) -> Literal["tools", "__end__"]:
    last = s["messages"][-1]
    return "tools" if getattr(last, "tool_calls", None) else END
STEP 4 · 연결하고 실행 (루프 한도 포함)
예시 답안 보기
g = StateGraph(MessagesState)
g.add_node("agent", agent); g.add_node("tools", tools)
g.add_edge(START, "agent")
g.add_conditional_edges("agent", should_continue)
g.add_edge("tools", "agent")                          # 루프
react = g.compile()

for q in ["VPN이 안 붙어요", "안녕하세요"]:
    out = react.invoke({"messages": [HumanMessage(content=q)]}, {"recursion_limit": 10})
    print([type(m).__name__ for m in out["messages"]], "→", out["messages"][-1].content)
['HumanMessage', 'AIMessage', 'ToolMessage', 'AIMessage'] → 점검 결과: VPN 서버 정상. 재접속해 보세요.
['HumanMessage', 'AIMessage'] → 무엇을 도와드릴까요?
STEP 5 · 확인과 확장
