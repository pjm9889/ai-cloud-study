이 노트북에서 만드는 것

일반 RAG는 "검색 → 생성"으로 끝나지만, Self-RAG는 중간중간 LLM이 스스로 결과를 평가(self-grading)하고, 부족하면 질문을 고쳐 다시 검색하거나 답을 다시 만듭니다.

단계 하는 일 사용하는 체인
① 검색 질문으로 벡터 DB 검색 retriever
② 문서 평가 검색된 문서가 질문과 관련 있는지 yes/no retrieval_grader
③ 생성 관련 문서를 근거로 답변 rag_chain
④ 환각 평가 답변이 문서에 근거하는지 yes/no hallucination_grader
⑤ 유용성 평가 답변이 질문을 해결하는지 yes/no answer_grader
⑥ 질문 재작성 검색이 잘 되도록 질문을 다시 씀 question_rewriter

버전 안내: 원문은 2024년 LangChain 0.x 기준입니다. LangChain 1.x / LangGraph 1.x에서 바뀐 import 경로는 각 셀의 ⚠ 주석에 대체 코드를 적었습니다.

Self-RAG¶

Self-RAG is a strategy for RAG that incorporates self-reflection / self-grading on retrieved documents and generations.

In the paper, a few decisions are made:

  1. Should I retrieve from retriever, R -
  • Input: x (question) OR x (question), y (generation)
  • Decides when to retrieve D chunks with R
  • Output: yes, no, continue
  1. Are the retrieved passages D relevant to the question x -
    • Input: (x (question), d (chunk)) for d in D
  • d provides useful information to solve x
  • Output: relevant, irrelevant
  1. Are the LLM generation from each chunk in D is relevant to the chunk (hallucinations, etc) -
  • Input: x (question), d (chunk), y (generation) for d in D
  • All of the verification-worthy statements in y (generation) are supported by d
  • Output: {fully supported, partially supported, no support
  1. The LLM generation from each chunk in D is a useful response to x (question) -
  • Input: x (question), y (generation) for d in D
  • y (generation) is a useful response to x (question).
  • Output: {5, 4, 3, 2, 1}

We will implement some of these ideas from scratch using LangGraph.

📝 (한국어 요약) Self-RAG 논문의 4가지 판단¶

논문의 판단 질문 이 노트북에서
1. Retrieve? 지금 검색이 필요한가? 구현하지 않음 (항상 검색부터 시작)
2. 관련성 (ISREL) 검색된 문서가 질문과 관련 있는가? retrieval_grader + grade_documents 노드
3. 근거성 (ISSUP) 답변이 문서 내용에 근거하는가? (환각 여부) hallucination_grader
4. 유용성 (ISUSE) 답변이 질문에 쓸모 있는가? answer_grader

논문은 이 판단들을 모델이 특수 토큰으로 직접 출력하도록 학습시키지만, 여기서는 학습 없이 별도의 LLM 평가 체인으로 같은 역할을 흉내 냅니다. 논문의 점수(1~5, fully/partially supported)는 모두 yes/no 이진 판정으로 단순화했습니다.

🔎 Retriever 설명¶

Self-RAG 그래프가 검색할 지식 창고를 만듭니다. 블로그 글 3개를 250토큰 조각으로 잘라 Chroma 벡터 DB에 넣고, 질문과 의미가 가까운 조각을 찾아 주는 retriever를 만듭니다.

In [1]:
# ============================================================
# [Retriever 만들기] 블로그 글 3개를 벡터 DB에 넣고 검색기로 만든다
# ------------------------------------------------------------
# 흐름:  URL → 문서 로드 → 작은 조각(chunk)으로 자르기 → 임베딩 → Chroma 저장 → retriever
# Self-RAG 그래프의 retrieve 노드가 이 retriever 를 사용합니다.
# ============================================================
from langchain.text_splitter import RecursiveCharacterTextSplitter
# ⚠ LangChain 1.x: from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import WebBaseLoader
from langchain_community.vectorstores import Chroma
# ⚠ 최신 권장: from langchain_chroma import Chroma  (pip install langchain-chroma)
from langchain_openai import OpenAIEmbeddings

# 검색 대상이 될 지식: Lilian Weng 블로그 글 3개 (에이전트 / 프롬프트 엔지니어링 / LLM 적대적 공격)
urls = [
    "https://lilianweng.github.io/posts/2023-06-23-agent/",
    "https://lilianweng.github.io/posts/2023-03-15-prompt-engineering/",
    "https://lilianweng.github.io/posts/2023-10-25-adv-attack-llm/",
]

# 1) 문서 로드: URL 하나마다 Document 리스트가 나오므로 결과는 "리스트의 리스트"
docs = [WebBaseLoader(url).load() for url in urls]
# 2) 리스트의 리스트를 한 줄로 펼치기 (flatten)
docs_list = [item for sublist in docs for item in sublist]

# 3) 자르기: tiktoken 토큰 기준으로 250토큰씩, 겹침 없이(chunk_overlap=0)
#    - 조각이 작을수록 검색이 정밀해지지만 문맥이 끊길 수 있음
#    - 실무에서는 overlap 을 10~20% 정도 주는 경우가 많음
text_splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
    chunk_size=250, chunk_overlap=0
)
doc_splits = text_splitter.split_documents(docs_list)

# 4) 벡터 DB에 저장 (Add to vectorDB)
#    각 조각을 OpenAIEmbeddings 로 벡터화해 "rag-chroma" 컬렉션에 넣는다.
#    persist_directory 를 주지 않았으므로 메모리에만 있음 → 커널 재시작 시 다시 만들어야 함
vectorstore = Chroma.from_documents(
    documents=doc_splits,
    collection_name="rag-chroma",
    embedding=OpenAIEmbeddings(),
)

# 5) 검색기로 변환: 기본값은 유사도 상위 4개 문서를 돌려줌
#    (개수를 바꾸려면 vectorstore.as_retriever(search_kwargs={"k": 6}))
retriever = vectorstore.as_retriever()

LLMs¶

🤖 LLM 체인 5개 설명¶

그래프의 노드와 라우터가 사용할 부품을 미리 만들고, 셀마다 단독으로 시험해 봅니다.

체인 입력 출력 그래프에서 쓰는 곳
retrieval_grader question, document binary_score yes/no grade_documents 노드
rag_chain context, question 답변 문자열 generate 노드
hallucination_grader documents, generation binary_score yes/no 라우터 2 (1단계)
answer_grader question, generation binary_score yes/no 라우터 2 (2단계)
question_rewriter question 새 질문 문자열 transform_query 노드

평가자 3개는 모두 with_structured_output으로 정해진 형식(yes/no) 만 돌려받기 때문에, 그래프의 분기 조건이 안정적입니다.

### Retrieval Grader  (논문의 판단 ②: 검색된 문서가 질문과 관련 있는가?)
# ============================================================
# [문서 관련성 평가기]
# ------------------------------------------------------------
# 검색된 문서 한 개와 질문을 LLM 에 보여 주고 "yes / no" 로 관련성을 판정합니다.
# 그래프의 grade_documents 노드가 문서마다 이 평가기를 호출해, 관련 없는 문서를 걸러 냅니다.
#
# 핵심 기법: with_structured_output
#   LLM 이 자유 문장이 아니라 지정한 스키마(GradeDocuments)에 맞는 객체를 돌려주게 합니다.
#   → 결과를 score.binary_score 처럼 바로 꺼내 쓸 수 있어 if 분기가 안정적입니다.
# ============================================================

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.pydantic_v1 import BaseModel, Field
# ⚠ langchain_core.pydantic_v1 은 지원 종료(최신 langchain-core 에서는 제거됨).
#    최신 코드:  from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI


# 출력 스키마(Data model): LLM 이 채워서 돌려줄 형식
#   - 클래스 docstring 과 Field 의 description 이 LLM 에게 "무엇을 채워야 하는지" 알려 주는 설명서 역할
class GradeDocuments(BaseModel):
    """Binary score for relevance check on retrieved documents."""

    binary_score: str = Field(
        description="Documents are relevant to the question, 'yes' or 'no'"
    )
    # 💡 개선 아이디어: str 대신 Literal["yes", "no"] 로 쓰면 다른 값이 나올 여지를 더 줄일 수 있음


# 평가용 LLM: temperature=0 → 같은 입력이면 최대한 같은 판정 (평가자는 일관성이 중요)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_llm_grader = llm.with_structured_output(GradeDocuments)

# 프롬프트: "엄격하지 않아도 된다, 엉뚱한 검색 결과만 걸러라"
#   → 관련 키워드나 의미가 조금이라도 있으면 yes. 너무 엄격하면 쓸 만한 문서까지 버려 재검색이 잦아짐
system = """You are a grader assessing relevance of a retrieved document to a user question. \n 
    It does not need to be a stringent test. The goal is to filter out erroneous retrievals. \n
    If the document contains keyword(s) or semantic meaning related to the user question, grade it as relevant. \n
    Give a binary score 'yes' or 'no' score to indicate whether the document is relevant to the question."""
grade_prompt = ChatPromptTemplate.from_messages(
    [
        ("system", system),
        ("human", "Retrieved document: \n\n {document} \n\n User question: {question}"),
    ]
)

# 체인: 프롬프트 → 구조화 출력 LLM   (입력 {"question", "document"} → GradeDocuments 객체)
retrieval_grader = grade_prompt | structured_llm_grader

# --- 단독 테스트 ---
question = "agent memory"
docs = retriever.get_relevant_documents(question)
# ⚠ get_relevant_documents 는 지원 종료 예정 → 최신 코드: docs = retriever.invoke(question)
doc_txt = docs[1].page_content          # 검색 결과 중 두 번째 문서의 본문으로 시험
print(retrieval_grader.invoke({"question": question, "document": doc_txt}))
# 예상 출력: binary_score='yes'

### Generate  (검색된 문서를 근거로 답변 생성)
# ============================================================
# [답변 생성 체인]
# ------------------------------------------------------------
# LangChain Hub 의 표준 RAG 프롬프트 "rlm/rag-prompt" 를 내려받아 사용합니다.
#   이 프롬프트는 {context}(근거 문서)와 {question}(질문) 두 변수를 받습니다.
# 그래프의 generate 노드가 이 rag_chain 을 호출합니다.
# ============================================================

from langchain import hub
# ⚠ LangChain 1.x 에서는 langchain.hub 가 빠졌습니다.
#    pip install langchain-classic 후 from langchain_classic import hub
#    또는 프롬프트를 직접 작성: ChatPromptTemplate.from_template("...{context}...{question}...")
from langchain_core.output_parsers import StrOutputParser

# Prompt: Hub 에서 공개 프롬프트 가져오기 (인터넷 연결 필요)
prompt = hub.pull("rlm/rag-prompt")

# LLM: 원문은 gpt-3.5-turbo 사용 (현재는 gpt-4o-mini 등 최신 모델로 바꿔도 됨)
llm = ChatOpenAI(model_name="gpt-3.5-turbo", temperature=0)


# Post-processing: Document 리스트를 "본문만 이어 붙인 문자열"로 바꾸는 함수
def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)
# ⚠ 이 함수는 정의만 되고 아래 체인에서 쓰이지 않습니다.
#    그래서 context 에 Document 객체 리스트가 그대로 문자열화되어 들어갑니다
#    (metadata 까지 프롬프트에 섞여 토큰 낭비).
#    개선: rag_chain.invoke({"context": format_docs(docs), "question": question})


# Chain: 프롬프트 → LLM → 문자열 파서  (AIMessage 에서 .content 만 꺼냄)
rag_chain = prompt | llm | StrOutputParser()

# Run: 앞 셀에서 검색한 docs 와 question("agent memory")으로 시험 생성
generation = rag_chain.invoke({"context": docs, "question": question})
print(generation)

### Hallucination Grader  (논문의 판단 ③: 답변이 문서에 근거하는가?)
# ============================================================
# [환각 평가기]
# ------------------------------------------------------------
# "검색된 사실들(documents)"과 "LLM 답변(generation)"을 보여 주고,
# 답변이 문서에 근거(grounded)하면 yes, 문서에 없는 내용을 지어냈으면 no.
#
# 그래프에서의 역할: generate 다음의 조건부 엣지(grade_generation_v_documents_and_question)가
#   먼저 이 평가기를 부르고, no 이면 "not supported" → generate 를 다시 실행합니다.
# ============================================================


# 출력 스키마: yes = 문서에 근거함 / no = 환각 있음
class GradeHallucinations(BaseModel):
    """Binary score for hallucination present in generation answer."""

    binary_score: str = Field(
        description="Answer is grounded in the facts, 'yes' or 'no'"
    )


# 평가 LLM (temperature=0 으로 일관된 판정)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_llm_grader = llm.with_structured_output(GradeHallucinations)

# 프롬프트: "답변이 사실 집합에 근거/지지되는가?"
system = """You are a grader assessing whether an LLM generation is grounded in / supported by a set of retrieved facts. \n 
     Give a binary score 'yes' or 'no'. 'Yes' means that the answer is grounded in / supported by the set of facts."""
hallucination_prompt = ChatPromptTemplate.from_messages(
    [
        ("system", system),
        ("human", "Set of facts: \n\n {documents} \n\n LLM generation: {generation}"),
    ]
)

# 체인: 입력 {"documents", "generation"} → GradeHallucinations
hallucination_grader = hallucination_prompt | structured_llm_grader

# 단독 테스트: 앞 셀의 docs / generation 으로 판정
hallucination_grader.invoke({"documents": docs, "generation": generation})
# 예상 출력: GradeHallucinations(binary_score='yes')

### Answer Grader  (논문의 판단 ④: 답변이 질문에 실제로 도움이 되는가?)
# ============================================================
# [답변 유용성 평가기]
# ------------------------------------------------------------
# 환각이 없어도(문서에 근거해도) 질문에 대한 답이 아닐 수 있습니다.
#   예) 질문: "에이전트 메모리 종류는?"  답변: 문서에 있는 "에이전트의 정의"만 설명
# 질문과 답변을 보여 주고 "질문을 해결하는가?"를 yes / no 로 판정합니다.
#
# 그래프에서의 역할: 환각 평가가 yes 일 때만 이어서 호출.
#   yes → "useful" → END,   no → "not useful" → transform_query(질문 재작성)
# ============================================================


# 출력 스키마: yes = 질문을 해결함
class GradeAnswer(BaseModel):
    """Binary score to assess answer addresses question."""

    binary_score: str = Field(
        description="Answer addresses the question, 'yes' or 'no'"
    )


# 평가 LLM
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_llm_grader = llm.with_structured_output(GradeAnswer)

# 프롬프트: "답변이 질문을 다루는가/해결하는가?"
system = """You are a grader assessing whether an answer addresses / resolves a question \n 
     Give a binary score 'yes' or 'no'. Yes' means that the answer resolves the question."""
answer_prompt = ChatPromptTemplate.from_messages(
    [
        ("system", system),
        ("human", "User question: \n\n {question} \n\n LLM generation: {generation}"),
    ]
)

# 체인: 입력 {"question", "generation"} → GradeAnswer
answer_grader = answer_prompt | structured_llm_grader

# 단독 테스트
answer_grader.invoke({"question": question, "generation": generation})

# ============================================================
# [질문 재작성기]
# ------------------------------------------------------------
# 사용자의 질문은 짧거나 모호한 경우가 많습니다("agent memory").
# 벡터 검색에 유리하도록 의도를 풀어 쓴 질문으로 바꿉니다.
#   예) "agent memory" → "What are the different types of memory used by LLM-based agents?"
#
# 그래프에서 쓰이는 두 경우:
#   ① grade_documents 결과 관련 문서가 하나도 없을 때  → transform_query → retrieve
#   ② 답변이 질문을 해결하지 못할 때("not useful")   → transform_query → retrieve
# 출력이 구조화된 객체가 아니라 "질문 문자열"이므로 StrOutputParser 로 끝납니다.

system = """You a question re-writer that converts an input question to a better version that is optimized \n

re_write_prompt = ChatPromptTemplate.from_messages(

        ("system", system),
        (
            "human",

        ),
    ]
)

# 체인: 입력 {"question"} → 재작성된 질문(str)
question_rewriter = re_write_prompt | llm | StrOutputParser()

# 단독 테스트
question_rewriter.invoke({"question": question})

Graph state¶

🧭 그래프 설계 설명¶

LangGraph로 위 부품들을 흐름으로 연결합니다.

  • State(상태): 노드들이 함께 쓰는 메모 — question, generation, documents
  • Node(노드): 일을 하는 함수 — retrieve / grade_documents / generate / transform_query
  • Edge(엣지): 다음 노드를 정하는 함수 — decide_to_generate, grade_generation_v_documents_and_question

두 개의 루프가 있다는 점이 핵심입니다.

  1. 관련 문서가 없거나 답이 질문을 못 풀면 → transform_query → retrieve (재검색 루프)
  2. 답변에 환각이 있으면 → generate (재생성 루프)

⚠ 원문에는 루프 횟수 제한이 없습니다. 실습할 때는 recursion_limit을 지정하거나 retry_count 상태를 추가해 보세요.

# ============================================================
# [그래프 상태(State) 정의]
# ------------------------------------------------------------
# 모든 노드가 함께 읽고 쓰는 "공유 메모"입니다.
# 리듀서(Annotated[..., add] 등)가 없으므로 세 키 모두 "덮어쓰기" 방식:
#   노드가 {"documents": [...]} 를 돌려주면 이전 documents 는 새 값으로 교체됩니다.
#   → grade_documents 가 관련 문서만 남긴 리스트로 덮어쓰는 동작이 바로 이것을 이용합니다.
# ============================================================
from typing import List

from typing_extensions import TypedDict


class GraphState(TypedDict):
    """
    Represents the state of our graph.

    Attributes:
        question: question          # 현재 질문 (transform_query 가 재작성하면 바뀜)
        generation: LLM generation  # generate 노드가 만든 답변
        documents: list of documents  # 검색 결과 → 평가 후 관련 문서만 남은 리스트
    """

    question: str
    generation: str
    documents: List[str]
    # ⚠ 실제로 들어가는 값은 문자열이 아니라 langchain Document 객체 리스트입니다.
    #    타입을 정확히 쓰려면: from langchain_core.documents import Document → List[Document]

    # 💡 개선 아이디어: 무한 루프 방지용 카운터
    #    retry_count: int   (아래 "Edges" 셀의 주석 참고)

### Nodes  ─────────────────────────────────────────────────────
# 노드 = "일을 하는 함수".  state(dict)를 받아, 바꿀 키만 dict 로 돌려줍니다.
# 원문은 바뀌지 않은 키(question 등)도 함께 돌려주는데, 덮어쓰기 키라 결과는 같습니다.
# (바꿀 키만 돌려줘도 충분합니다.)


def retrieve(state):
    """
    Retrieve documents

    Args:
        state (dict): The current graph state

    Returns:
        state (dict): New key added to state, documents, that contains retrieved documents
    """
    # [검색 노드] 현재 질문으로 벡터 DB 를 검색해 documents 를 채운다
    print("---RETRIEVE---")
    question = state["question"]

    # Retrieval: 유사도 상위 문서(기본 4개)
    documents = retriever.get_relevant_documents(question)   # ⚠ 최신: retriever.invoke(question)
    return {"documents": documents, "question": question}


def generate(state):
    """
    Generate answer

    Args:
        state (dict): The current graph state

    Returns:
        state (dict): New key added to state, generation, that contains LLM generation
    """
    # [생성 노드] 남아 있는(관련 있다고 판정된) 문서를 근거로 답변을 만든다
    print("---GENERATE---")
    question = state["question"]
    documents = state["documents"]

    # RAG generation  (💡 format_docs(documents) 를 쓰면 프롬프트가 깔끔해짐)
    generation = rag_chain.invoke({"context": documents, "question": question})
    return {"documents": documents, "question": question, "generation": generation}


def grade_documents(state):
    """
    Determines whether the retrieved documents are relevant to the question.

    Args:
        state (dict): The current graph state

    Returns:
        state (dict): Updates documents key with only filtered relevant documents
    """
    # [문서 평가 노드] 문서마다 retrieval_grader 로 yes/no 판정 → yes 인 것만 남긴다
    print("---CHECK DOCUMENT RELEVANCE TO QUESTION---")
    question = state["question"]
    documents = state["documents"]

    # Score each doc  (문서 수만큼 LLM 호출 → 문서가 많으면 느림)
    # 💡 개선: retrieval_grader.batch([...]) 로 한 번에 병렬 호출하거나,
    #         Send API 로 문서별 평가를 병렬 노드로 나눌 수 있음
    filtered_docs = []
    for d in documents:
        score = retrieval_grader.invoke(
            {"question": question, "document": d.page_content}
        )
        grade = score.binary_score
        if grade == "yes":
            print("---GRADE: DOCUMENT RELEVANT---")
            filtered_docs.append(d)
        else:
            print("---GRADE: DOCUMENT NOT RELEVANT---")
            continue
    # documents 를 "관련 문서만" 으로 덮어쓴다 → 다음 라우터가 비었는지 확인
    return {"documents": filtered_docs, "question": question}


def transform_query(state):
    """
    Transform the query to produce a better question.

    Args:
        state (dict): The current graph state

    Returns:
        state (dict): Updates question key with a re-phrased question
    """
    # [질문 재작성 노드] question 을 검색에 유리한 문장으로 바꾼다 → 다음은 retrieve (재검색)
    print("---TRANSFORM QUERY---")
    question = state["question"]
    documents = state["documents"]

    # Re-write question
    better_question = question_rewriter.invoke({"question": question})
    # 💡 무한 루프 방지: 여기서 {"retry_count": state.get("retry_count", 0) + 1} 도 함께 돌려주면 좋음
    return {"documents": documents, "question": better_question}


### Edges  ─────────────────────────────────────────────────────
# 엣지(라우터) = "다음에 어디로 갈지" 정하는 함수.
#   상태를 읽기만 하고, 다음 노드를 가리키는 "문자열"을 돌려줍니다.
#   돌려준 문자열은 아래 Build Graph 셀의 add_conditional_edges 매핑 키와 정확히 같아야 합니다.


def decide_to_generate(state):
    """
    Determines whether to generate an answer, or re-generate a question.

    Args:
        state (dict): The current graph state

    Returns:
        str: Binary decision for next node to call
    """
    # [라우터 1] grade_documents 다음: 관련 문서가 남았나?
    #   - 하나도 없으면 → "transform_query" (질문 재작성 후 재검색)
    #   - 있으면       → "generate"
    print("---ASSESS GRADED DOCUMENTS---")
    state["question"]   # (원문 그대로. 값을 쓰지 않는 줄이라 지워도 동작은 같음)
    filtered_documents = state["documents"]

    if not filtered_documents:
        # All documents have been filtered check_relevance
        # We will re-generate a new query
        print(
            "---DECISION: ALL DOCUMENTS ARE NOT RELEVANT TO QUESTION, TRANSFORM QUERY---"
        )
        return "transform_query"
    else:
        # We have relevant documents, so generate answer
        print("---DECISION: GENERATE---")
        return "generate"


def grade_generation_v_documents_and_question(state):
    """
    Determines whether the generation is grounded in the document and answers question.

    Args:
        state (dict): The current graph state

    Returns:
        str: Decision for next node to call
    """
    # [라우터 2] generate 다음: 두 단계 검사
    #   1단계 환각 검사(hallucination_grader): 답변이 문서에 근거하는가?
    #       no  → "not supported" → generate 다시 (같은 문서로 재생성)
    #   2단계 유용성 검사(answer_grader): 답변이 질문을 해결하는가?
    #       yes → "useful"      → END (완료)
    #       no  → "not useful"  → transform_query (질문 재작성 → 재검색)
    print("---CHECK HALLUCINATIONS---")
    question = state["question"]
    documents = state["documents"]
    generation = state["generation"]

    score = hallucination_grader.invoke(
        {"documents": documents, "generation": generation}
    )
    grade = score.binary_score

    # Check hallucination
    if grade == "yes":
        print("---DECISION: GENERATION IS GROUNDED IN DOCUMENTS---")
        # Check question-answering
        print("---GRADE GENERATION vs QUESTION---")
        score = answer_grader.invoke({"question": question, "generation": generation})
        grade = score.binary_score
        if grade == "yes":
            print("---DECISION: GENERATION ADDRESSES QUESTION---")
            return "useful"
        else:
            print("---DECISION: GENERATION DOES NOT ADDRESS QUESTION---")
            return "not useful"
    else:
        # ⚠ pprint 는 이 셀에서 import 하지 않았습니다. 마지막 실행 셀에서 import 한 뒤
        #   그래프를 실행하므로 동작하지만, 이 함수만 따로 실행하면 NameError 가 납니다.
        #   print 로 바꾸거나 이 셀 위에 from pprint import pprint 를 두면 안전합니다.
        pprint("---DECISION: GENERATION IS NOT GROUNDED IN DOCUMENTS, RE-TRY---")
        return "not supported"

# ⚠ 무한 루프 주의
#   "not supported" → generate → 또 환각 → generate ... 처럼 종료 조건(횟수 제한)이 없습니다.
#   transform_query ↔ retrieve 루프도 마찬가지입니다.
#   대책: ① GraphState 에 retry_count 를 두고 일정 횟수를 넘으면 END 로 보내기
#         ② 실행 시 app.invoke(inputs, {"recursion_limit": 20}) 로 상한 지정

🏗️ 그래프 조립 설명¶

add_node로 노드를 등록하고, add_edge(항상 같은 다음 노드)와 add_conditional_edges(라우터 함수의 반환 문자열 → 다음 노드)로 연결합니다. 마지막 compile()로 실행 가능한 app을 만듭니다.

In [10]:
# ============================================================
# [그래프 조립]  노드 등록 → 엣지 연결 → 컴파일
# ------------------------------------------------------------
# 흐름 요약
#   START → retrieve → grade_documents ─┬─(관련 문서 있음)──→ generate ─┬─ useful ───────→ END
#                    ↑                  └─(관련 문서 없음)──→ transform_query   ├─ not supported → generate (재생성)
#                    └──────────────────── transform_query ←──────────────────────┘ not useful
# ============================================================
from langgraph.graph import END, StateGraph, START

workflow = StateGraph(GraphState)   # 위에서 정의한 상태 스키마로 그래프 생성

# Define the nodes : add_node("노드 이름", 함수)
workflow.add_node("retrieve", retrieve)  # retrieve        : 벡터 검색
workflow.add_node("grade_documents", grade_documents)  # grade documents : 관련 문서만 남김
workflow.add_node("generate", generate)  # generate        : 답변 생성
workflow.add_node("transform_query", transform_query)  # transform_query : 질문 재작성

# Build graph
workflow.add_edge(START, "retrieve")                   # 시작하면 항상 검색부터
workflow.add_edge("retrieve", "grade_documents")       # 검색 후 항상 문서 평가

# 조건부 엣지 1: 문서 평가 후 → 라우터(decide_to_generate)의 반환값으로 분기
#   딕셔너리 = { 라우터가 돌려주는 문자열 : 실제로 이동할 노드 이름 }
workflow.add_conditional_edges(
    "grade_documents",
    decide_to_generate,
    {
        "transform_query": "transform_query",
        "generate": "generate",
    },
)

workflow.add_edge("transform_query", "retrieve")       # 질문을 고쳤으면 다시 검색 (루프)

# 조건부 엣지 2: 답변 생성 후 → 환각·유용성 검사 결과로 분기 (Self-RAG 의 "자기 반성" 단계)
workflow.add_conditional_edges(
    "generate",
    grade_generation_v_documents_and_question,
    {
        "not supported": "generate",      # 환각 있음 → 같은 문서로 다시 생성
        "useful": END,                    # 근거 있고 질문도 해결 → 종료
        "not useful": "transform_query",  # 근거는 있지만 질문을 못 풂 → 질문 재작성
    },
)

# Compile: 실행 가능한 그래프(app)로 변환. (구조 검사도 이때 이루어짐)
#   💡 대화 기억·중단 후 재개가 필요하면 compile(checkpointer=InMemorySaver())
app = workflow.compile()

✅ 정리와 실습 아이디어¶

  • Self-RAG = 검색 → 문서 평가 → 생성 → 환각 평가 → 유용성 평가, 부족하면 질문 재작성/재생성 루프
  • 평가자를 with_structured_output으로 만들면 라우터의 if 분기가 단순하고 안정적
  • 실습 과제
    1. GraphState에 retry_count를 추가하고 3회를 넘으면 END(또는 "모르겠습니다" 답변)로 보내기
    2. generate에서 format_docs(documents)를 쓰도록 바꾸고 답변 품질 비교하기
    3. grade_documents의 문서별 평가를 retrieval_grader.batch(...)로 바꿔 속도 비교하기
    4. LangChain 1.x import 경로(⚠ 주석)로 모두 바꿔 최신 환경에서 실행하기
