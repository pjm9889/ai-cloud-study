03. OpenSearch 실행 — 보안 ON(로그인 방식)

📍 어디서 PowerShell · 01_설치_명령.ps1✅ 먼저 02탭
PowerShell · 비밀번호를 한 번만 정해 두기
$env:OS_PW = "여기에-강한-비밀번호"   # 대문자·소문자·숫자·특수문자 포함 8자 이상
PowerShell · OpenSearch 실행
docker run -d --name opensearch `
  -p 9200:9200 `
  -e "discovery.type=single-node" `
  -e "OPENSEARCH_INITIAL_ADMIN_PASSWORD=$env:OS_PW" `
  -e "OPENSEARCH_JAVA_OPTS=-Xms512m -Xmx512m" `
  -v opensearch-secure-data:/usr/share/opensearch/data `
  opensearchproject/opensearch:latest
옵션뜻
-d --name opensearch뒤에서 실행, 컨테이너 이름은 opensearch (이후 모든 명령이 이 이름을 씀)
-p 9200:9200내 PC 9200 → 컨테이너 9200 (API)
discovery.type=single-node노드 1개짜리 실습 클러스터
OPENSEARCH_INITIAL_ADMIN_PASSWORDadmin 계정의 첫 비밀번호. 보안 플러그인이 켜진 상태로 시작 → https + 로그인
OPENSEARCH_JAVA_OPTS메모리 512MB (실습용으로 작게)
-v opensearch-secure-data:...데이터를 볼륨에 저장 → 컨테이너를 지워도 인덱스는 남음
이렇게 풀어서 설명합니다

비밀번호가 약하면(예: admin123) OpenSearch가 시작하자마자 꺼집니다. docker logs opensearch에 비밀번호 강도 관련 메시지가 보이면 더 강한 비밀번호로 컨테이너를 지우고 다시 만듭니다. 이 비밀번호는 이후 Dashboards 로그인, curl, Python .env에 모두 똑같이 씁니다(A4-M1 13탭의 로그인 방식).

비밀번호를 문서에 평문으로 남기지 않기

실습 명령도 $env:OS_PW처럼 변수로 쓰고, Python은 .env에서 읽습니다. 공유하는 교안·화면 캡처·채팅에 실제 비밀번호를 붙여 넣지 않습니다.

06. Nori란 — 토크나이저와 분석기의 차이

검색엔진의 “분석”은 세 단계입니다. 글자 다듬기(char filter) → 자르기(tokenizer) → 토큰 다듬기(token filter). Nori는 자르기 단계와 다듬기 단계를 한국어용으로 제공합니다.

"배송이 조금 늦었어요"
   │ standard tokenizer : 띄어쓰기로 자름       → 배송이 | 조금 | 늦었어요
   │ nori_tokenizer     : 형태소로 자름          → 배송 | 이 | 조금 | 늦 | 었 | 어요   (조사·어미도 토큰)
   │ nori 분석기        : nori_tokenizer
   │                       + nori_part_of_speech  (조사·어미 등 품사 제거)
   │                       + nori_readingform     (한자 → 한글)
   │                       + lowercase            → 배송 | 늦   (조사·어미, 부사 '조금'도 기본 제거)
   ↓
색인·검색에 쓰이는 토큰
Nori 구성 요소종류하는 일
nori_tokenizertokenizer형태소 단위로 자르고 품사를 붙임. 옵션: decompound_mode, user_dictionary(_rules)
nori_part_of_speechtoken filter지정한 품사(기본: 조사·어미·부사·관형사·감탄사·접사·기호 등 — 10탭 표의 ✂)를 버림
nori_readingformtoken filter한자를 한글 읽기로 (會議 → 회의)
nori_numbertoken filter한글 숫자를 아라비아 숫자로 (일억 → 100000000)
norianalyzer위를 묶어 둔 기성품 (tokenizer + part_of_speech + readingform + lowercase)
이렇게 풀어서 설명합니다

설치 확인 때 자주 쓰는 "tokenizer": "nori_tokenizer"는 자르기만 하므로 결과에 “에”, “를” 같은 조사가 그대로 나옵니다(07탭 실제 결과). 검색에 쓸 때는 조사를 떼는 분석기("analyzer": "nori" 또는 직접 만든 custom 분석기)를 씁니다. “Nori를 깔았는데 조사가 그대로 나와요”는 대부분 이 둘을 헷갈린 경우입니다.

Python · 품사 이름을 몰라도 되는 방법 (explain의 leftPOS로 거르기 — 03_nori_python.py nouns)
res = client.indices.analyze(body={"tokenizer": "nori_tokenizer", "text": "노트북 성능은 좋은데 배송이 조금 늦었어요",
                                   "explain": True, "attributes": ["leftPOS"]})
tokens = res["detail"]["tokenizer"]["tokens"]
print([t["token"] for t in tokens if t["leftPOS"].startswith("NNG")])        # ("NNG", "NNP")로 여러 개도

② decompound_mode — 복합명사를 어떻게 남기나

Dev Tools · none / discard / mixed 바꿔 가며 (position도 함께)
POST _analyze?filter_path=tokens.token,tokens.position
{
  "tokenizer": { "type": "nori_tokenizer", "decompound_mode": "mixed" },
  "text": "형태소 분석기를 추가했습니다"
}
값“노트북” / “형태소”좋은 점나쁜 점
none노트북 / 형태소원래 단어로 정확히“노트”로는 못 찾음
discard (기본)노트 · 북 / 형태 · 소 (실제 확인)부분 단어로 찾음원래 단어가 사라짐, “북”처럼 엉뚱한 조각
mixed노트북 · 노트 · 북 / 형태소 · 형태 · 소둘 다 — 검색용으로 무난토큰 수 증가, “북”은 여전히 남음
mixed에서 position 보기

원래 단어와 첫 조각이 같은 position(예: 형태소 0, 형태 0)을 가집니다. 그래서 “형태소 분석기”를 match_phrase로 찾아도 순서가 깨지지 않습니다. NNG 필터와 합치면 "tokenizer": {"type": "nori_tokenizer", "decompound_mode": "mixed"} + ①의 filter → 노트북 · 노트 · 북 · 성능 · 배송이 나올 것으로 예상합니다.

def tokens_with_pos(text, decompound_mode="discard"):
    res = client.indices.analyze(body={
        "tokenizer": {"type": "nori_tokenizer", "decompound_mode": decompound_mode},
        "text": text, "explain": True, "attributes": ["posType", "leftPOS", "rightPOS"]})
    return [(t["token"], t.get("posType"), t.get("leftPOS", "")) for t in res["detail"]["tokenizer"]["tokens"]]

def nouns(text, tags=("NNG",)):
    return [tok for tok, _, pos in tokens_with_pos(text) if pos.startswith(tags)]
