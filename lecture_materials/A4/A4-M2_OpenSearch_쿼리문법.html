가장 많이 헷갈리는 것이 “21”과 “2”의 차이입니다. 서울 주문은 21건이지만, size를 2로 했으니 문서는 2건만 왔습니다. 그리고 합계 58,566,750원은 받은 2건이 아니라 조건에 맞는 21건 전체로 계산한 값입니다. aggs는 size와 상관없이 query가 고른 문서 전부를 봅니다.

실무 질문은 조건이 두 개 이상입니다. bool은 조건을 네 칸에 나눠 담습니다. 칸마다 “반드시인지, 점수에 넣을지”가 다릅니다.

📍 어디서 Dev Tools✅ 먼저 02·03탭

미션 5 · SQL → DSL → Python

  1. Query Workbench나 Dev Tools에서 SELECT product, AVG(satisfaction) FROM sales WHERE region='대구' GROUP BY product를 실행합니다.
  2. 같은 SQL을 _plugins/_sql/_explain에 넣어 DSL을 받습니다.
  3. 그 DSL(또는 직접 쓴 DSL)을 Python client.search로 실행해 제품별 평균 만족도를 출력합니다.
정답 (Python)
Python
body = {"size": 0,
        "query": {"term": {"region": "대구"}},
        "aggs": {"p": {"terms": {"field": "product"},
                       "aggs": {"sat": {"avg": {"field": "satisfaction"}}}}}}
res = client.search(index="sales", body=body)
for b in res["aggregations"]["p"]["buckets"]:
    print(b["key"], b["doc_count"], round(b["sat"]["value"], 2))

# SQL을 Python에서 바로
sql = client.transport.perform_request("POST", "/_plugins/_sql",
        body={"query": "SELECT product, AVG(satisfaction) FROM sales WHERE region='대구' GROUP BY product"})
print(sql["datarows"])

두 방식의 숫자가 같아야 합니다. _explain이 준 DSL은 내가 쓴 것보다 길 수 있지만 결과는 같습니다.

미션 6 · GPT가 만든 틀린 쿼리 고치기

아래는 “서울의 제품별 매출을 큰 순서로”를 GPT에게 물어 받은 답이라고 가정합니다. 실행하면 오류가 나거나 결과가 비어 있습니다. 11탭 체크리스트로 세 군데를 찾아 고칩니다.

틀린 쿼리
GET sales/_search
{
  "size": 0,
  "query": { "match": { "region.keyword": "서울" } },
  "aggs": {
    "products": {
      "terms": { "field": "product", "order": { "total": "desc" } },
      "aggs": { "revenue_sum": { "sum": { "field": "revenue" } } }
    }
  }
}
정답

① region.keyword → region: 우리 매핑에는 .keyword 하위 필드가 없습니다. 이대로면 오류 없이 0건이고 집계가 비어 있습니다. ② match → term: keyword 필드라 결과는 같지만, 정확한 값 조건은 term(가능하면 bool filter)이 의도에 맞습니다. ③ "order": {"total": "desc"} → {"revenue_sum": "desc"}: 정렬 이름은 안쪽 집계 이름과 같아야 합니다. 없는 이름이면 오류가 납니다. 고친 뒤 결과는 노트북 21,360,000 → 복합기 17,000,000 → 프로젝터 9,506,000 순입니다.
