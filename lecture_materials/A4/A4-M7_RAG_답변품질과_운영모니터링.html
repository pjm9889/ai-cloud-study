02. 답변 품질 4가지 — 근거성 · 충실성 · 관련성 · 완전성

검색이 맞아도 GPT는 숫자를 바꾸거나, 의미를 과장하거나, 딴소리를 하거나, 절반만 답할 수 있습니다. 네 가지를 이 실습 문서 하나로 구분해 봅니다.

근거 · docs/서울/2026_서울_공공기관_노트북전략.md 중 “제안 전략”
## 제안 전략
- 제품 코드 NB-SEOUL-26 기준 제안서 사용
- 3년 유지보수 조건 명시
- 대량 납품 일정과 설치 범위 명확화
- 조달 절차에 맞춘 문서 제공
지표묻는 것실패하는 답변 예 (질문: 2026 서울 공공기관 노트북 전략은?)
Groundedness 근거성답의 내용이 근거 안에 실제로 있나?“5년 유지보수 조건을 명시합니다.” — 근거에 없는 숫자
Faithfulness 충실성근거의 의미·강도·조건을 바꾸지 않았나?“3년 유지보수는 법으로 정해진 필수 조건입니다.” — ‘명시’를 ‘법적 필수’로 과장
Answer Relevance 관련성물은 것에 답했나?“서울 지역은 기업과 공공기관 고객이 모두 존재합니다.” — 사실이지만 전략이 아님
Completeness 완전성핵심을 빠뜨리지 않았나?(비교 질문에) 2026년만 설명하고 2025년은 빠뜨림
이렇게 풀어서 설명합니다

근거성은 “있는 걸 말했나”, 충실성은 “있는 걸 그대로 말했나”입니다. 3년이라는 숫자는 맞는데 ‘명시’가 ‘법적 필수’로 바뀌면 근거성은 통과, 충실성은 실패입니다. 영업 현장에서는 이런 과장이 계약 분쟁이 됩니다.

용어 주의

Groundedness와 Faithfulness는 평가 도구마다 정의가 겹칩니다. Ragas는 Faithfulness를 “답의 주장이 검색 근거로 뒷받침되는가”로, Microsoft Foundry는 Groundedness를 “답이 근거와 일치하고 지어낸 것이 없는가”로 설명합니다. 이 교안에서는 위 표처럼 있나(근거성) / 그대로인가(충실성)로 나눠 배우되, 업계 전체의 별개 표준이라고 단정하지 않습니다.

12. Reliability — 재시도와 오류율

정확해도 자주 끊기면 운영할 수 없습니다. s09는 GPT 호출이 실패하면 1초 → 2초 → 4초 쉬며 최대 3번 시도하고, 그 횟수를 기록합니다.

src/s09_answer.py · call_llm (핵심)
for attempt in range(MAX_RETRIES):          # 최대 3번
    try:
        ans, i, o = _openai(messages)
        return ans, i, o, ms, retries, None   # 성공
    except Exception as e:                    # Timeout · Rate limit · 서버 오류
        last_err = f"{type(e).__name__}: {e}"
        retries += 1
        time.sleep(2 ** attempt)              # 1초, 2초, 4초 — exponential backoff
return "", 0, 0, 0.0, retries, last_err       # 끝내 실패 → error 기록

좋은 RAG는 “답이 그럴듯한 시스템”이 아니라 검색과 답변을 각각 숫자로 잴 수 있고, 실패 원인을 추적할 수 있고, 시간이 지나도 나빠지지 않았는지 확인할 수 있는 시스템입니다. 사용자가 “답이 이상하다”고 하면 Data → Retrieval → Answer → Operations 순서로, 각 층의 숫자와 로그를 따라 내려갑니다.
