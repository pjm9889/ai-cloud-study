.env는 “이 컴퓨터에서만 쓰는 비밀 메모”입니다. config.py의 load_dotenv()가 이 파일을 읽어 os.getenv("OPENAI_API_KEY")로 꺼내 씁니다. 코드에 키를 직접 쓰면 코드를 공유하는 순간 키도 함께 퍼지기 때문에 이렇게 분리합니다.

.env 관리 규칙

① 줄마다 이름=값, 등호 앞뒤 공백·따옴표 없이 씁니다. ② 이 모듈에 필요 없는 다른 키(예: 다른 서비스 API 키)가 함께 있어도 동작에는 상관없습니다. ③ .env는 다른 사람에게 보내거나 GitHub에 올리지 않습니다. 공유할 때는 값을 지운 .env.example을 만들어 줍니다. ④ 파일 이름이 정확히 .env인지 확인합니다. Windows 메모장으로 저장하면 .env.txt가 되는 경우가 많습니다.

clients.py — 로그인한 OpenSearch에 연결

clients.py
from openai import OpenAI
from opensearchpy import OpenSearch
from config import (OPENAI_API_KEY, OPENSEARCH_PASSWORD,
                    OPENSEARCH_HOST, OPENSEARCH_PORT, OPENSEARCH_USER)

def get_openai_client():
    if not OPENAI_API_KEY:
        raise ValueError(".env의 OPENAI_API_KEY를 확인하세요.")
    return OpenAI(api_key=OPENAI_API_KEY)

def get_opensearch_client():
    if not OPENSEARCH_PASSWORD:
        raise ValueError(".env의 OPENSEARCH_PASSWORD를 확인하세요.")
    return OpenSearch(
        hosts=[{"host": OPENSEARCH_HOST, "port": OPENSEARCH_PORT}],
        http_auth=(OPENSEARCH_USER, OPENSEARCH_PASSWORD),   # admin / 비밀번호로 로그인
        use_ssl=True,                                        # https
        verify_certs=False,                                  # 로컬 자체서명 인증서
    )

def chunk_markdown(text):
    parts = re.split(r"\n(?=## )", text)          # '## '로 시작하는 줄 앞에서 자르기
    chunks = [part.strip() for part in parts
              if part.strip().startswith("## ")]   # 맨 앞 '# 제목'과 안내문 조각은 버림
    return chunks

def make_embeddings(openai_client, chunks):
    response = openai_client.embeddings.create(model=EMBEDDING_MODEL, input=chunks)
    vectors = np.array([item.embedding for item in response.data], dtype="float32")
    faiss.normalize_L2(vectors)                       # 길이 1로 → 내적 = 코사인
    return vectors

def save_faiss(chunks, vectors):
    FAISS_DIR.mkdir(exist_ok=True)
    index = faiss.IndexFlatIP(vectors.shape[1])        # 1536차원, 전부 비교(정확 검색)
    index.add(vectors)
    faiss.write_index(index, str(FAISS_INDEX_PATH))   # 벡터 → index.faiss
    CHUNKS_PATH.write_text(json.dumps(chunks, ensure_ascii=False, indent=2),
                           encoding="utf-8")          # 원문 → chunks.json
    return index

from clients import get_opensearch_client
from config import SALES_INDEX

def get_net_revenue(os_client, region):
    result = os_client.search(index=SALES_INDEX, body={
        "size": 0,
        "query": {"bool": {
            "filter":   [{"term": {"region": region}}],
            "must_not": [____________________________],
        }},
        "aggs": {"net_revenue": {"sum": {"field": "revenue"}}},
    })
    return result["aggregations"]["net_revenue"]["value"]

os_client = get_opensearch_client()
for r in ["서울", "광주"]:
    print(r, f"{get_net_revenue(os_client, r):,.0f}원")

한 문장 복습

Q. 매출 합계를 GPT에게 직접 계산시키지 않는 이유는?

언어 모델은 긴 숫자 계산을 틀리기 쉽고 틀려도 그럴듯하게 말합니다. 계산은 OpenSearch 집계, 설명은 GPT로 나눕니다.

Q. 이번 모듈에서 FAISS를 쓴 이유와, OpenSearch 벡터로 옮길 때는?

조각 6개뿐인 고정 문서라 파일 두 개로 충분합니다. 문서가 많아지거나 필터·공동 갱신이 필요하면 OpenSearch knn_vector로 옮깁니다(A4-M3).

Q. FAISS 저장 파일이 두 개인 이유는?

index.faiss는 벡터와 번호만 알고, chunks.json이 번호와 원문을 연결합니다.

Q. 통합 RAG 프롬프트에서 두 근거의 역할은?

FAISS 문서 = 지역·시장·고객 특성의 근거, OpenSearch 집계 = 실제 주문·매출·수량의 근거. 둘을 비교하고 없는 숫자는 만들지 않습니다.
